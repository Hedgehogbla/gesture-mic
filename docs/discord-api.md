# Discord API: с нуля и почему мут не через неё

Короткая шпаргалка, чтобы понимать, что такое API, и почему эта программа
нажимает клавишу, а не «дёргает Discord по API».

## 1. Что такое API

API — это договор: «отправь такой запрос — получишь такой ответ». Обычно это
HTTP поверх интернета. Запрос состоит из четырёх частей:

```
GET https://discord.com/api/v10/gateway
│   │                              │
│   │                              └── путь (что просим)
│   └── адрес сервера
└── метод: GET (прочитать), POST (создать), PATCH (изменить), DELETE (удалить)
```

Плюс заголовки (headers) — метаданные: кто мы, какой формат хотим. И тело
(body) — данные, обычно JSON.

Ответ — тоже HTTP: **статус-код** + заголовки + тело.

| Код | Значение |
|---|---|
| 200 | OK |
| 401 | не авторизован (нет или протух токен) |
| 403 | авторизован, но нет прав |
| 404 | не найдено |
| 429 | слишком много запросов (rate limit) |

## 2. Первый запрос — без токена

```powershell
Invoke-RestMethod https://discord.com/api/v10/gateway
```

Ответ:

```
url
---
wss://gateway.discord.gg
```

Это публичный эндпоинт: он просто говорит, куда подключаться. Никакого
аккаунта не нужно. Так выглядит «прочитать данные» — метод GET, без тела.

## 3. Авторизация: токен бота

Приватные эндпоинты требуют заголовок:

```
Authorization: Bot <ваш_токен>
User-Agent: DiscordBot (https://example.com, 1.0)
```

Токен — это пароль от бота. Правила:

- хранить только в переменной окружения, никогда в коде и в git;
- если токен попал в репозиторий — считать его скомпрометированным и
  перевыпустить в Discord Developer Portal;
- `.gitignore` не спасает, если файл уже закоммичен — история хранит всё.

```powershell
$env:DISCORD_TOKEN = "..."   # только на текущую сессию терминала
```

## 4. Что Discord API умеет с микрофоном

Умеет **серверный мут участника**:

```
PATCH /api/v10/guilds/{guild_id}/members/{user_id}
{ "mute": true }
```

Требования: бот состоит на сервере, имеет право `MUTE_MEMBERS`, а участник —
на этом сервере. Это не «ваш мут», а мут, который сервер применяет к человеку.
В личных сообщениях и в клиенте это не работает.

Чего API **не** умеет:

- выключить микрофон в вашем собственном клиенте;
- нажать кнопку mute в интерфейсе Discord;
- изменить ваши личные настройки голоса.

Локальный RPC, который когда-то позволял менять voice settings, устарел и
больше не является поддерживаемым способом. OAuth2 даёт доступ к аккаунту,
но не к состоянию кнопки mute в запущенном клиенте.

Вывод: единственный официальный способ переключить **свой** мут — горячая
клавиша, которую слушает клиент. Её и нажимает `mute.py`.

## 5. Rate limits

Discord ограничивает частоту запросов. При превышении приходит `429` и JSON
с полем `retry_after` (секунды). Правильное поведение — подождать и повторить,
а не долбить сервер. Наши жесты и так ограничены `cooldown_ms`, но это про
другое: у API свой счётчик.

## 6. Как потренироваться

1. [Discord Developer Portal](https://discord.com/developers/applications) →
   **New Application** → **Bot** → **Reset Token**.
2. Пригласить бота на свой тестовый сервер (OAuth2 URL Generator, scope `bot`,
   право `Manage Roles` или `Mute Members`).
3. Положить токен в переменную окружения и прочитать список серверов:

```powershell
$headers = @{ Authorization = "Bot $env:DISCORD_TOKEN" }
Invoke-RestMethod -Headers $headers https://discord.com/api/v10/users/@me/guilds
```

4. Дальше — `GET /guilds/{id}/members?limit=10`, `PATCH` для мута и т.д.
   Полный список: <https://discord.com/developers/docs>.

Так вы учитесь на настоящем API, но не пытаетесь делать им то, чего он не
умеет.
